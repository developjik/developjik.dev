# 폰트 로딩 전략: FOIT/FOUT에서 preload까지

## 개요

웹폰트를 쓰면 폰트 파일이 내려올 때까지 텍스트가 어떻게 보일지 결정됩니다. 폰트가 도착할 때까지 텍스트를 숨기면 FOIT(Flash of Invisible Text), 시스템 폰트로 먼저 보여주면 FOUT(Flash of Unstyled Text)가 발생합니다. 어느 쪽이든 사용자 경험에 흔적이 남기 때문에, 이 글에서는 이 문제를 단계적으로 다듬은 과정을 정리합니다.

## font-display 옵션 이해하기

`@font-face`의 `font-display` 디스크립터는 폰트 로딩 중 텍스트 처리를 정합니다.

- `auto`: 브라우저 기본 동작
- `block`: 짧은 블록 기간(~3초) 동안 텍스트를 숨겼다가, 폰트가 늦으면 fallback으로 전환
- `swap`: 즉시 fallback을 보여주고 폰트가 도착하면 교체
- `fallback`: 약 100ms 블록 후 fallback, 폰트가 도착하면 교체 (늦으면 교체 안 함)
- `optional`: 브라우저가 판단해 폰트를 아예 안 쓸 수도 있음

```css
@font-face {
  font-family: 'Pretendard';
  src: url('/fonts/PretendardVariable.woff2') format('woff2');
  font-weight: 45 920;
  font-display: swap;
}
```

본문 텍스트에는 `swap`이 무난했습니다. 콘텐츠가 늦게라도 보이는 편이 빈 화면보다 낫기 때문입니다.

## preload로 폰트 발견 시점 앞당기기

폰트 파일은 보통 CSS 안에서 발견되기 때문에, CSSOM이 만들어진 뒤에야 다운로드가 시작됩니다. 이 지연을 줄이려면 `preload`로 힌트를 줍니다.

```html
<link
  rel="preload"
  href="/fonts/PretendardVariable.woff2"
  as="font"
  type="font/woff2"
  crossorigin
/>
```

여기서 `crossorigin`을 빠뜨리면 폰트가 이중으로 다운로드됩니다. 폰트는 CORS 모드로 가져오기 때문에 preload에도 같은 모드를 지정해야 브라우저가 요청을 재사용합니다. 이거 하나 때문에 한참을 헤맸습니다.

## fallback 폰트 메트릭 맞춤

`swap`을 쓰면 폰트 교체 시점에 레이아웃 시프트(CLS)가 발생합니다. fallback 폰트와 웹폰트의 x-height, 자간이 다르면 텍스트 높이와 줄바꿈이 달라지기 때문입니다. `size-adjust`, `ascent-override` 등으로 fallback의 메트릭을 조정해 차이를 줄일 수 있습니다.

```css
@font-face {
  font-family: 'Pretendard-fallback';
  src: local('Apple SD Gothic Neo');
  size-adjust: 96%;
  ascent-override: 92%;
}

body {
  font-family: 'Pretendard', 'Pretendard-fallback', sans-serif;
}
```

조정 전에는 폰트 교체 시 CLS가 눈에 띄게 측정됐는데, 메트릭을 맞춘 뒤에는 시프트가 거의 보이지 않았습니다. capice 같은 도구로 fallback 메트릭을 계산해주니 그 후로는 수작업하지 않습니다.

## 서브셋과 woff2

한글 폰트는 글리프 수가 많아 파일이 큽니다. 가변 폰트나 서브셋(자주 쓰는 글자만 포함)으로 파일 크기를 줄이고, woff2 포맷을 쓰면 압축 효율이 더 좋습니다. Pretendard처럼 이미 서브셋/가변 버전을 제공하는 경우 그대로 쓰는 게 가장 편합니다.

## 마무리

정리하면 제 폰트 로딩 전략은 이렇습니다. woff2 + 가변 폰트로 크기를 줄이고, `preload`로 발견 시점을 앞당기고, `font-display: swap`으로 콘텐츠를 즉시 보여주고, 메트릭 조정된 fallback으로 시프트를 최소화합니다. 각 단계는 독립적으로 적용할 수 있으니 하나씩 측정하며 도입해보시길 권합니다.
