# 시맨틱 HTML: 왜 div를 쓰지 않는가

## 개요

코드 리뷰를 하다 보면 화면은 완벽한데 마크업이 `div`와 `span`으로만 이루어진 경우를 자주 봅니다. 동작에는 문제가 없어 보이지만, 이런 마크업은 스크린 리더 사용자와 검색 엔진에게는 벽에 막힌 것과 같습니다. 시맨틱 HTML이 왜 필요하고 실제로 어떻게 바꿔야 하는지 제 경험을 섞어 정리해봤습니다.

## 시맨틱 요소가 주는 의미

HTML의 모든 요소는 자신만의 의미(semantics)를 가집니다. `<nav>`는 내비게이션 영역이고, `<button>`은 클릭 가능한 인터랙션이며, `<h1>`은 페이지의 최상위 제목입니다. 반면 `div`와 `span`은 아무 의미가 없는 그릇입니다.

이 의미가 실제로 작동하는 곳이 두 군데 있습니다.

- **접근성**: 스크린 리더는 시맨틱 요소를 통해 "여기는 내비게이션이다", "이것은 버튼이다"라고 사용자에게 알립니다. `<button>`은 포커스, 엔터/스페이스 키 활성화, 폼 제출 같은 브라우저 기본 동작도 함께 제공합니다.
- **SEO**: 검색 엔진 크롤러도 마크업의 의미를 사용해 페이지 구조를 이해합니다. 문서의 개요가 `<h1>`~`<h6>`과 랜드마크 요소로 명확하면 콘텐츠를 더 잘 해석할 수 있습니다.

## 잘못된 div 중첩의 전형

실제로 리뷰에서 봤던 패턴을 간소화해보면 이런 모습입니다.

```html
<div class="header">
  <div class="nav">
    <div class="nav-item" onclick="go('/home')">홈</div>
    <div class="nav-item" onclick="go('/about')">소개</div>
  </div>
</div>

<div class="main">
  <div class="title">서비스 소개</div>
  <div class="content">여기에 본문이 있습니다.</div>
  <div class="btn" onclick="submit()">제출</div>
</div>
```

눈으로 보기엔 완벽한 페이지지만, 키보드로는 내비게이션에 접근할 수 없고(onclick만 있어 포커스 대상이 아님), 스크린 리더 사용자는 이 페이지의 제목이 무엇인지 알 수 없습니다.

## 리팩터링: 시맨틱 요소로 바꾸기

위 마크업을 시맨틱하게 고치면 이렇게 됩니다.

```html
<header>
  <nav aria-label="주요 메뉴">
    <ul>
      <li><a href="/home">홈</a></li>
      <li><a href="/about">소개</a></li>
    </ul>
  </nav>
</header>

<main>
  <h1>서비스 소개</h1>
  <p>여기에 본문이 있습니다.</p>
  <button type="button" onclick="submit()">제출</button>
</main>
```

바뀐 점을 정리하면 다음과 같습니다.

- `div.header` → `<header>`: 랜드마크로 읽혀 바로 영역을 탐색할 수 있습니다.
- `div.nav` → `<nav>` + `<ul>`: 스크린 리더가 "내비게이션, 항목 2개"라고 안내합니다.
- `div.nav-item`의 onclick → `<a>`: 링크는 링크답게. 키보드 접근과 상황별 메뉴가 기본 제공됩니다.
- `div.title` → `<h1>`: 페이지 개요의 최상위로 인식됩니다.
- `div.btn` → `<button>`: 포커스, 키보드 활성화가 공짜로 따라옵니다.

## ARIA는 마지막 수단

"접근성이 필요하면 ARIA를 붙이면 되지 않나?"라는 질문을 종류 받습니다. WAI-ARIA의 첫 규칙은 명확합니다. **네이티브 HTML로 해결할 수 있다면 ARIA를 쓰지 마세요.** `role="button"`을 붙인 `div`는 `tabindex`, 키보드 핸들러, `aria-pressed` 관리를 직접 다 해야 하지만, `<button>`은 그냥 동작합니다.

```html
<!-- 이렇게 하지 말고 -->
<div role="button" tabindex="0" onkeydown="handleKey(event)">제출</div>

<!-- 이렇게 -->
<button type="button">제출</button>
```

## 더 알아보기

리팩터링할 때 참고했던 기준을 공유합니다.

- 문서 개요: 페이지마다 `<h1>` 하나, 제목 단계를 건너뛰지 않기
- 랜드마크: `<header>`, `<nav>`, `<main>`, `<footer>`, `<aside>`로 페이지 골격 잡기
- 목록은 `<ul>`/`<ol>`, 인용은 `<blockquote>`, 강조는 `<strong>`/`<em>`처럼 의미에 맞는 요소 사용하기
- 시각적 이유만 있다면 `div`는 여전히 정당합니다. "div 금지"가 아니라 "의미가 있을 때 시맨틱 요소"가 원칙입니다

마크업 하나를 바꾸는 것만으로 키보드 사용자와 스크린 리더 사용자의 경험이 달라집니다. 새 기능을 만들 때 CSS를 먼저 생각하지 말고, 이 콘텐츠의 의미가 무엇인지부터 물어보세요. 그 답이 곧 마크업입니다.
