# Svelte 5 Runes 심층 가이드 — $state, $derived, $effect와 컴파일러 기반 반응성

## 개요

[Svelte 5가 2024년 10월 22일 안정 버전으로 발표](https://svelte.dev/blog/svelte-5-is-alive)되었습니다. 약 18개월의 개발 끝에 나온 이 버전은 프로젝트 역사상 가장 큰 변화입니다. 프레임워크가 처음부터 다시 쓰였고, 반응성을 다루는 방식이 통째로 바뀌었습니다. 그 중심에 있는 것이 룬(runes)입니다.

룬은 `$state`, `$derived`, `$effect`처럼 달러 기호로 시작하는 컴파일러 지시어입니다. 컴파일러가 이 신호를 보고 코드를 세밀한(fine-grained) 반응형 코드로 변환합니다. 이 글은 룬 하나하나를 문서와 실제 사용 경험을 기준으로 정리하고, 기존 Svelte 4 문법과 비교하며, 마이그레이션까지 다루는 가이드입니다.

## 배경: Svelte 4 반응성의 한계

Svelte 3/4의 반응성은 "컴파일러가 다 해줌"이 미덕이었습니다. `let`으로 선언한 변수에 할당하면 컴파일러가 그 사실을 감지해 `invalidate` 코드를 심습니다. 편했지만 근본적인 한계가 있었습니다. [공식 발표문](https://svelte.dev/blog/svelte-5-is-alive)은 이를 솔직하게 설명합니다.

- **객체 전체 무효화**: 반응형 객체의 프로퍼티 하나를 바꿔도 컴파일러가 감지할 수 있는 단위는 "그 객체" 전체였습니다. 어떤 부분이 바뀌었는지 세밀하게 알 수 없으니 불필요하게 넓게 다시 렌더링됩니다. 같은 기간 다른 프레임워크들은 신호(signal) 기반 세밀한 반응성으로 성능을 끌어올렸고, Svelte는 역전당했습니다.
- **`$:` 문법의 함정**: `$:`로 반응형 문장을 실행할 때 의존성은 그 문장이 "실행될 때"가 아니라 "컴파일될 때" 결정됩니다. 리팩터링에 약하고, 파생 상태(derived state)와 사이드 이펙트(effect)라는 다른 개념을 하나의 문법에 뭉뚱그려 담았습니다. 복잡한 앱에서는 어느새 `$:` 지옥이 되곤 했습니다.
- **이벤트와 슬롯의 어색함**: `on:click` 이벤트와 `<slot>` 콘텐츠는 prop과 다른 별도의 개념이었습니다. 컴포넌트 합성에 필요한 개념이 세 벌이었던 셈입니다.

Svelte 5는 이 세 가지를 각각 룬, 이벤트 핸들러의 prop화, snippet으로 해결했습니다.

## Runes가 반응성을 다루는 방식

룬의 핵심 아이디어는 **반응성을 암묵적 규칙이 아니라 명시적 신호로 선언**하는 것입니다. 컴파일러는 룬이 선언된 지점을 보고 어떤 값이 상태이고, 어떤 값이 파생인지, 어떤 코드가 이펙트인지 정확하게 압니다. 그 결과 Svelte의 전통적인 장점은 그대로 유지하면서도 signal 수준의 세밀함을 얻었습니다.

```svelte
<script>
  let count = $state(0);
</script>

<button onclick={() => count++}>
  클릭 {count}회
</button>
```

`count`는 여전히 그냥 숫자입니다. 다른 프레임워크처럼 `count.value`를 읽거나 `setCount`를 부르는 것이 아니라, 평범한 JavaScript처럼 읽고 쓰면 됩니다. 반응성은 값이 아니라 코드를 컴파일하는 방식에 있으니까요.

또 하나 중요한 변화는 룬이 `.svelte` 컴포넌트뿐 아니라 `.svelte.js`/`.svelte.ts` 모듈에서도 쓸 수 있다는 점입니다. 컴포넌트 바깥에서 재사용 가능한 반응형 로직을 같은 문법으로 만들 수 있게 되었습니다.

```ts
// counter.svelte.ts
export function createCounter() {
  let count = $state(0);
  return {
    get count() {
      return count;
    },
    increment: () => count++,
    reset: () => (count = 0),
  };
}
```

## $state와 $state.raw, $state.snapshot

`$state`는 반응형 상태를 선언하는 룬입니다. 객체와 배열에 쓰면 **프록시(proxy)** 로 감싸져 깊은(deep) 반응성을 갖습니다.

```svelte
<script>
  let todos = $state([
    { id: 1, text: 'Runes 문서 읽기', done: false },
  ]);

  function add(text: string) {
    // push 자체가 반응성을 유발합니다. 재할당이 필요 없습니다.
    todos.push({ id: Date.now(), text, done: false });
  }
</script>

<ul>
  {#each todos as todo (todo.id)}
    <li>
      <label>
        <input type="checkbox" bind:checked={todo.done} />
        {todo.text}
      </label>
    </li>
  {/each}
</ul>
```

`todos.push(...)` 하나로 목록이 업데이트되고, `todo.done` 하나를 바꾸면 그 체크박스만 갱신됩니다. Svelte 4라면 배열 재할당, 객체 통째로 교체를 신경 써야 했던 부분입니다.

세 가지 변형이 더 있습니다.

- **`$state.raw`**: 프록시 없이 참조 변경(재할당)에만 반응합니다. 불변 업데이트 스타일을 선호하거나, 값이 매우 커서 프록시 오버헤드를 피하고 싶을 때 씁니다.

```svelte
<script>
  let options = $state.raw({ theme: 'dark', density: 'compact' });

  function toggleTheme() {
    // 재할당해야 반응합니다. 프로퍼티 변경은 무시됩니다.
    options = { ...options, theme: options.theme === 'dark' ? 'light' : 'dark' };
  }
</script>
```

- **`$state.snapshot`**: 반응형 프록시를 일반 객체로 완전히 복제합니다. `JSON.stringify`나 구조 분해가 필요한 순간, `structuredClone` 대신 쓰는 안전한 방법입니다.

```js
console.log(JSON.stringify($state.snapshot(todos)));
```

## $derived와 $derived.by

파생 상태는 `$derived`로 선언합니다. 의존성은 문법적으로 자동 추적되므로, 읽는 값이 바뀌면 재계산됩니다.

```svelte
<script>
  let price = $state(4500);
  let count = $state(1);
  let total = $derived(price * count);
</script>
```

계산이 한 줄에 안 들어가면 `$derived.by`를 씁니다. 함수 안에서 읽은 반응형 값이 모두 의존성이 됩니다.

```svelte
<script>
  let names = ['Svelte', 'Runes', 'Signal', 'Compiler'];
  let query = $state('');

  let results = $derived.by(() => {
    const q = query.trim().toLowerCase();
    if (!q) return names;
    return names.filter((name) => name.toLowerCase().includes(q));
  });
</script>

<input bind:value={query} />
<ul>
  {#each results as name (name)}
    <li>{name}</li>
  {/each}
</ul>
```

`$:` 시절의 트릭(의존성을 터치하기 위해 변수를 읽어두기)은 이제 필요 없습니다. 의존성은 런타임에 실제로 읽은 값으로 결정되므로, 로직을 함수로 추출해도 동작이 유지됩니다.

## $effect와 $effect.pre

사이드 이펙트는 `$effect`입니다. 컴포넌트 마운트 후, 그리고 의존성이 바뀔 때 실행되며, 함수가 반환한 cleanup는 정리 시점에 호출됩니다.

```svelte
<script>
  let width = $state(0);

  $effect(() => {
    const onResize = () => (width = window.innerWidth);
    onResize();
    window.addEventListener('resize', onResize);
    return () => window.removeEventListener('resize', onResize);
  });
</script>

<p>현재 창 너비: {width}px</p>
```

`$effect`는 DOM이 업데이트된 **이후**에 실행됩니다. 화면에 그려진 상태를 기준으로 측정하거나 로깅할 때 씁니다. 반대로 `$effect.pre`는 DOM 업데이트 **직전**에 실행되어, 화면이 그려지기 전에 값을 조정해야 할 때 사용합니다. 둘의 구분은 Svelte 4의 `$:`와 `beforeUpdate`/`afterUpdate`가 뒤섞여 있던 책임을 명확히 나눈 결과입니다.

한 가지 원칙을 기억해야 합니다. **파생될 수 있는 값은 `$derived`로, 외부 세계와 동기화해야만 하는 작업만 `$effect`로.** 로컬 상태를 `$effect` 안에서 바꾸는 코드는 대부분 `$derived`로 다시 쓸 수 있고, 그 편이 예측 가능합니다. [모범 사례 문서](https://svelte.dev/docs/svelte/best-practices)도 같은 가이드를 줍니다.

## $props와 $bindable

컴포넌트 props는 이제 `export let` 대신 `$props` 룬으로 선언합니다. 구조 분해, 기본값, 나머지 연산이 자연스럽게 동작합니다.

```svelte
<!-- Section.svelte -->
<script>
  import type { Snippet } from 'svelte';

  let {
    title,
    tone = 'plain',
    children,
    ...rest
  }: { title: string; tone?: 'plain' | 'accent'; children: Snippet; [key: string]: unknown } = $props();
</script>

<section class={tone} {...rest}>
  <h2>{title}</h2>
  {@render children()}
</section>
```

자식에서 부모로 값이 거슬러 올라가는 양방향 바인딩이 필요하면 `$bindable`로 props를 표시합니다.

```svelte
<!-- SearchBox.svelte -->
<script>
  let { value = $bindable(''), placeholder = '검색어 입력' } = $props();
</script>

<input bind:value {placeholder} />
```

```svelte
<script>
  import SearchBox from './SearchBox.svelte';
  let query = $state('');
</script>

<SearchBox bind:value={query} />
```

부모가 `bind:`를 안 쓰면 일반 단방향 prop처럼도 동작합니다. 데이터 흐름이 어긋나는 걸 허용하되, opt-in으로 열어두는 설계입니다.

## Snippet: slot의 완전한 대체

Svelte 5는 `<slot>`, `let:`, `<svelte:fragment>`를 없애고 snippet을 도입했습니다. snippet은 마크업 조각을 값처럼 만들고, 파라미터를 넘길 수 있습니다.

```svelte
<script>
  let products = $state([
    { id: 1, name: '기계식 키보드', price: 129000 },
    { id: 2, name: '마우스 패드', price: 21000 },
  ]);
</script>

{#snippet row(product)}
  <tr>
    <td>{product.name}</td>
    <td>{product.price.toLocaleString('ko-KR')}원</td>
  </tr>
{/snippet}

<table>
  <tbody>
    {#each products as product (product.id)}
      {@render row(product)}
    {/each}
  </tbody>
</table>
```

컴포넌트 경계를 넘길 때는 props로 전달하면 됩니다. 앞선 `Section.svelte`의 `children`이 바로 그 패턴입니다. 기본 콘텐츠는 `children`의 유무를 확인해 조건부로 렌더링하면 됩니다. 슬롯보다 개념이 하나 줄었고, 타입도 `Snippet`으로 깔끔하게 지정됩니다.

## 이벤트 핸들러와 그 밖의 변경

`on:click`은 이제 `onclick`입니다. 이벤트 핸들러는 특별한 존재가 아니라 평범한 prop이 되었습니다.

```svelte
<script>
  let { onsave } = $props();
</script>

<button onclick={() => onsave?.()}>저장</button>
```

그 밖에 눈에 띄는 변화는 네이티브 TypeScript 지원(전처리기 없이 `lang="ts"` 사용), 새 CLI인 `sv`의 등장 정도입니다. 상세한 목록은 [Svelte 5 마이그레이션 가이드](https://svelte.dev/docs/svelte/v5-migration-guide)에 정리되어 있습니다.

## 기존 `$:` 반응성과 나란히 보기

같은 로직을 Svelte 4와 Svelte 5로 쓰면 이렇게 다릅니다.

```svelte
<!-- Svelte 4 -->
<script>
  export let price = 0;
  let count = 0;

  $: total = price * count;
  $: if (total > 10000) {
    console.log('1만 원 초과:', total);
  }
</script>
```

```svelte
<!-- Svelte 5 -->
<script>
  let { price = 0 } = $props();
  let count = $state(0);

  let total = $derived(price * count);

  $effect(() => {
    if (total > 10000) {
      console.log('1만 원 초과:', total);
    }
  });
</script>
```

Svelte 4 버전에서 `total` 계산과 경고 출력이 `$:` 하나로 뒤섞여 있던 것이, Svelte 5에서는 **파생(`$derived`)** 과 **이펙트(`$effect`)** 로 갈라졌습니다. 의존성 추적이 런타임 기준으로 바뀌었으니 로직을 함수로 추출하거나 조건문 안으로 옮겨도 동작이 달라지지 않습니다. 제 경험에서 이게 체감이 가장 큰 변화였습니다.

## 마이그레이션: npx sv migrate svelte-5

좋은 소식부터. Svelte 5는 Svelte 4 문법과의 하위 호환성이 상당히 좋아서, 의존성만 올려도 대부분의 앱은 그대로 동작합니다(공식 표현은 "완전히 매끄러운 초기 업그레이드"). 새 문법으로의 전환은 별도 작업입니다.

```bash
# Svelte 3 사용 중이라면 먼저 4로 올립니다
npx sv migrate svelte-5
```

VS Code에서 Svelte 확장을 쓴다면 명령 팔레트의 "Migrate Component to Svelte 5 Syntax"로 컴포넌트 단위로 조금씩 옮길 수도 있습니다. 새 문법과 기존 문법은 한 프로젝트 안에서 섞일 수 있으니, 급하지 않다면 수정이 일어나는 컴포넌트부터 순차적으로 바꾸는 전략이 현실적입니다. 다만 Svelte 4 문법 지원은 언젠가 단계적으로 제거될 예정이라고 공지되어 있으니, 미루기만 하는 건 좋지 않습니다.

제 사이드 프로젝트에서는 마이그레이션 도구가 `$:` → `$derived`/`$effect`, `export let` → `$props`, `on:` → `on` 속성 전환을 대부분 자동으로 처리해줬습니다. 손을 댄 부분은 이벤트 디스패처(createEventDispatcher)를 쓰던 컴포넌트 콜백 prop으로 바꾼 것과, 슬롯 파라미터를 snippet 파라미터로 옮긴 것 정도였습니다. 옮기고 나면 런타임 의존성 추적 덕분에 이전에 이유를 찾기 어려웠던 갱신 누락 버그가 사라지는 경험도 합니다.

## 마치기

Runes는 "Svelte가 문법을 바꿨다" 이상의 의미가 있습니다. 컴파일러가 추론에 의존하던 반응성을 명시적 신호로 옮기면서, 사람이 읽을 때와 기계가 컴파일할 때의 모델이 같아졌습니다. 그 결과 세밀한 갱신, `.svelte.ts` 모듈 재사용, 파생/이펙트의 분리라는 실용적인 이득이 생겼습니다. React의 훅을 쓰다 온 사람이라면 익숙한 듯 다른 철학에, 순수 Svelte 사용자라면 새로운 규칙에 각각 적응이 필요하지만, 공식 문서와 마이그레이션 도구가 잘 갖춰져 있어 진입 장벽은 생각보다 낮습니다. 다음 프로젝트는 Svelte 5로 시작해도 충분합니다.
